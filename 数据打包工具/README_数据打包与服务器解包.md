# SO-101 数据打包与服务器解包

这个工具把采集笔记本上**选择的一个任务和版本的完整数据集**打成迁移包，用于拷贝到教学楼服务器的现有 LeRobot / ACT 训练环境。它不启动机械臂、不上传数据、不修改老师的训练环境。服务器读取和训练需在迁移后另行验证。

## 一、采集笔记本：选择数据并打包

1. 挂载 E 盘，完成对应任务所有已采集轮次的回放、质量及隐私审核，并在采集助手中关闭各轮。图像特征在 Parquet 中，不要只复制 `images/` 目录或单独 PNG。
2. 在图形终端或普通终端运行：

   ```bash
   bash "$HOME/fms688_data/SO101_数据打包工具/启动数据打包.sh"
   ```

3. 从列表输入编号，选择完整的 `<任务>/<版本>`；选择 0 退出。工具也会列出已有轮次但尚未生成数据的版本，并标明不能打包。仅查看列表可运行：

   ```bash
   bash "$HOME/fms688_data/SO101_数据打包工具/启动数据打包.sh" --list
   ```

4. 输入一个**已存在的输出目录**，或直接回车使用 `~/fms688_data/SO101_数据打包工具/打包结果/`。输入 `YES` 开始。输出目录不能位于正在打包的数据集或轮次目录中。
5. 等到提示“打包并校验完成”。工具输出一个 `.tar` 文件和同名 `.tar.sha256` 文件；**两者一起复制**。另需将本目录的 `服务器_校验解包.py` 一起复制到服务器，供服务器端使用。

工具只打包已通过审核且轮次关闭的完整数据集，检查六维动作/状态、双相机图像特征、元数据、Parquet、各轮 QA、数据隔离状态以及最新审核快照。采集程序的互斥锁用于阻止同时采集或审核；不要用其他程序绕过锁去改动源数据。异常退出遗留的 PNG、缺失元数据或正在采集的数据不会被当成可训练数据打包。工具不删除或修复源数据。

归档采用不压缩的 `.tar`，图像数据通常已经过编码；需要接近源数据大小的额外空间。脚本会先检查输出空间，再逐文件计算 SHA-256、写入、重新读包校验，耗时取决于数据大小。大文件中转盘也要支持大于 4 GiB 的单个文件；FAT32 不适合。

打包结构如下，保留 LeRobot 的 `meta/`、`data/` 和所有已关闭轮次的审核文件：

```text
数据包.tar
├── datasets/<任务>/<版本>/meta/...
├── datasets/<任务>/<版本>/data/...
├── rounds/<任务>/<版本>/r01/ROUND.md、SESSION.json、QA.csv、VALIDATION.json
├── rounds/<任务>/<版本>/r02/...        # 有后续已关闭轮次时
├── BUNDLE_MANIFEST.json                # 身份和逐文件校验值
└── README_解包与训练.txt
```

**当前采集状态**以实际机器为准。本工具在 2026-11-12 的只读检查中发现 `pick_t_container/20261111_pick_t_container` 有准备中的 `r01` 轮次，但尚未生成完整数据集，因此当前不能打包为训练数据。

## 二、训练服务器：自动校验和解包

把三个文件复制到服务器自己的临时目录：

- 数据包，例如 `so101_任务_版本_时间.tar`；
- 同名校验文件，例如 `so101_任务_版本_时间.tar.sha256`；
- `服务器_校验解包.py`。

在服务器自己的账号执行（将 `/实际路径/数据包.tar` 换成复制过去的真实路径）：

```bash
mkdir -p "$HOME/soarm101_dorm/imports"
python3 /实际路径/服务器_校验解包.py /实际路径/数据包.tar
```

校验脚本先检查 `.tar.sha256`，再创建一个全新的 `~/soarm101_dorm/imports/so101_<任务>_随机串/`，校验包内文件并解包；不会覆盖已有数据。若失败，按提示处理或重新复制；出现 `IMPORT_INCOMPLETE.txt` 的目录不能用于训练。要改导入根目录，先创建该目录，再加 `--destination /已有的目录`。

成功后，终端会打印两行 `export DS_ROOT=...` 和 `export REPO_ID=...`。**复制这两行到当前训练终端执行**；脚本作为子进程不能替你设置父终端环境变量。

用服务器已有 `station_act` 环境的 Python 验证样本，下面路径来自拷回的服务器资料，现场若不同请改为实际路径：

```bash
export PY=/home/server/miniconda3/envs/station_act/bin/python
"$PY" - <<'PY'
import os
from pathlib import Path
from lerobot.datasets.lerobot_dataset import LeRobotDataset

ds = LeRobotDataset(os.environ['REPO_ID'], root=Path(os.environ['DS_ROOT']))
assert len(ds) > 0, '数据集没有帧'
frame = ds[0]
for name in ('action', 'observation.state', 'observation.images.top', 'observation.images.wrist'):
    print(name, tuple(frame[name].shape))
print('READBACK OK:', len(ds), 'frames')
PY
```

确认六维动作/状态及双相机画面后，按工作区内的 `首次Act训练文本情况.txt/SO101_数据集判定与ACT训练服务器适配指南.md` 在健康、空闲 GPU 上先做短步数 ACT 冒烟；其中示例的 `DS_ROOT` 和 `REPO_ID` 要沿用上面实际解包路径与打印出的 ID。避免覆盖老师的 Lumos 数据或训练输出。

## 三、常见问题

- **显示未生成完整数据集**：轮次清单不等于录制成功；先完成采集、回放、检查和关闭。对于采集中断的残留文件，先查录制日志，不要自行删除源文件。
- **尚未关闭、审核未通过或数据发生变化**：回采集助手检查对应轮次，必要时重新审核；不要改清单或删除隔离文件来绕过。
- **提示正在采集或审核**：等待对应过程结束；不要删除锁文件。
- **空间不足**：选择已有的、空间充足且支持大文件的输出目录。
- **服务器 SHA-256 不通过**：两个文件一起重新复制，未通过前不要训练。
- **只想选部分 episode**：此版本按一个完整任务/版本打包；不会直接抽取单条轨迹，以免破坏 LeRobot 的索引与元数据。

```bash
source "$HOME/so101-lab/activate-lerobot.sh"
python "$HOME/fms688_data/SO101_数据打包工具/test_数据打包.py"
```

测试包含真实 LeRobot 临时数据集的打包、服务器辅助脚本解包、双路图像与动作读回，以及未关闭、隔离、源数据变更、锁占用、校验失败等情况；不访问真实机械臂或训练服务器。

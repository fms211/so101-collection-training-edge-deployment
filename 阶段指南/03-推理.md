# 第三阶段：Jetson 推理

将训练输出中的实际 checkpoint 与处理器从服务器传至笔记本，再传至 Jetson；核对模型输入、六个关节、两路相机和标定。依照[完整手册](../SO101采集-回放-打包-训练-本地推理全流程.md)和 [Jetson 方案](../SO101_Jetson边缘推理方案.md)配置环境，先运行 [离线 ACT 检查](../scripts/jetson/offline_act_check.py)，验证真实数据帧及模型处理器，离线检查不驱动机械臂。

实机必须经现场监督确认工作空间、机械臂状态及停止方式，再使用受控脚本和 `--confirm-physical`；仓库中的 `run_guarded_limit5.sh` 含原设备的具体环境、模型和设备路径，不能直接照搬。历史短时试运行退出成功不等于抓取成功，现阶段仍需实机验收。

## 无硬件离线检查示例

以下示例中的路径和数据集 ID 必须按实际情况替换。首先在有数据集及依赖的机器导出真实的一帧；输出含相机画面，应妥善保管和传输：

```bash
python scripts/jetson/offline_act_check.py export \
  --dataset-root /实际路径/数据集 --repo-id 用户名/数据集名 \
  --index 0 --output /安全位置/so101-sample.npz
```

将该样本和服务器训练出的完整 `pretrained_model` 目录经笔记本中转到 Jetson。在已准备好兼容环境的 Jetson 仓库目录执行，例如原机器使用的启动器：

```bash
so101-gpu-python scripts/jetson/offline_act_check.py infer \
  --model /实际路径/pretrained_model --sample /实际路径/so101-sample.npz --device cuda
```

`so101-gpu-python` 属于原 Jetson 实验环境，不包含在仓库内，也不适用于所有 Jetson。离线推理不会验证实际控制频率、硬件动作或抓取成功。

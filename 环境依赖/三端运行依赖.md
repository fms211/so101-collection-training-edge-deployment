# 三端运行依赖与检查

本清单分别对应笔记本采集、服务器训练、Jetson 边缘推理。Git 仓库只提供脚本和文档，**不会自动安装 Python、LeRobot、驱动、CUDA，也不包含环境、数据或模型**。以下版本是项目已有环境的记录；服务器与 Jetson 的状态需在对应机器重新读取。

## 1. 笔记本：自动化采集

- **系统与工具**：Linux 桌面、Bash、Git、Python 3.12；采集菜单录制选项需要 `gnome-terminal`、`script`（util-linux）、`v4l2-ctl`（v4l-utils）。设备列表、双摄预检和录制还需要 USB 串口与 V4L2 设备权限；当前进程应具备 `dialout`、`video` 权限，实际以设备节点读写权限为准。Rerun 显示需图形环境。
- **Python 环境**：项目当前固定 LeRobot **0.6.1**，本机实际是 Python 3.12.14；Feetech 支持、pyserial、OpenCV、PyArrow、datasets、NumPy、Pillow、pynput、Rerun 和 PyTorch 随 LeRobot 环境提供。`record_sent_action.py` 针对 0.6.1 录制器，升级版本前必须审查并测试。
- **现机参考**：[采集机 pip freeze 快照](采集笔记本-pip-freeze-20261113.txt)来自 2026-11-13 本机实际环境；源码提交为 `7e241bd630a3719a56157a497ce5d08f244784f1`。这是环境记录，不是跨平台一键安装锁文件：其中 CPU PyTorch 构建需匹配相应索引，操作系统库、Python 构建、索引和硬件不在快照里。不要把这份快照用于服务器或 Jetson。
- **硬件及数据**：主从臂、顶部和腕部相机均连接笔记本；准备各臂正确标定、稳定设备路径和足够空间的本地 SSD，`FMS688_DATA` 必须可写。网络传输可选用 OpenSSH、rsync；Hub 功能需 `hf` 和认证。

原采集机检查（其他机器先激活自己的 LeRobot 0.6.1 环境）：

```bash
source "$HOME/so101-lab/activate-lerobot.sh"
python --version
python -c 'import importlib.metadata as m; print("LeRobot", m.version("lerobot")); import cv2, numpy, pyarrow, torch; print("cv2", cv2.__version__, "torch", torch.__version__)'
python -m pip check
command -v lerobot-record lerobot-find-port lerobot-find-cameras v4l2-ctl gnome-terminal script
id -nG
```

换机安装起点（以下是独立环境的重建示例，**尚未在全新机器完整验证**；需有 Git、Python 3.12、venv 和 pip，并自行根据系统选择兼容的 PyTorch 包源）：

```bash
mkdir -p "$HOME/so101-lab/src"
git clone https://github.com/huggingface/lerobot.git "$HOME/so101-lab/src/lerobot-v0.6.1"
cd "$HOME/so101-lab/src/lerobot-v0.6.1"
git checkout 7e241bd630a3719a56157a497ce5d08f244784f1
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[feetech]"
```

如果目录已存在，不要重复克隆或覆盖，先核对其内容。此命令按依赖解析安装，并不保证重现快照中全部版本，也不会生成原机 `activate-lerobot.sh`；换机后每次先 `source "$HOME/so101-lab/src/lerobot-v0.6.1/.venv/bin/activate"`，再从本仓库启动菜单。安装后执行上面的命令（不要重复 source 原机专用激活脚本）、菜单 1 预检，以及模拟数据回归；若包解析或图形环境有问题，结合快照逐项排查，不要覆盖现有机器人或 ROS 环境。采集预检会访问相机，运行前确认设备未被其他程序占用。

## 2. 训练服务器：数据读回与 ACT

- **系统与工具**：Linux、Git、Python、SSH；远程持久训练建议 `tmux`；NVIDIA 驱动、可用 GPU 及与之匹配的 CUDA/PyTorch。打包的校验/解包工具本身使用 Python 标准库，训练读回另需 LeRobot、PyArrow 等。
- **项目服务器已有环境（历史记录）**：`station_act`，Python 3.12.14、LeRobot 0.6.2、PyTorch 2.11.0+cu130；根据实际环境确认。ACT 需 `lerobot-train`、datasets、PyArrow、NumPy、Pillow 等及可用的视觉骨干权重。多 GPU 启动器还需 `accelerate`；SmolVLA、VQ-BeT 的额外依赖及实际服务器支持情况需要另行验证，不应默认已安装。
- **隔离与兼容**：复用老师的环境前先检查，不要安装/升级包或覆盖老师的 Lumos 数据、模型和输出。历史服务器曾用 `so101_codec_python.sh` 解决进程级 torchcodec 库加载问题；它是服务器本机脚本，不在本仓库内，也不能假定换机可用。图像 Parquet 读回不需要先转视频。

在服务器实际环境中检查：

```bash
# 路径与环境名需与服务器实际情况一致
source /home/server/miniconda3/etc/profile.d/conda.sh
conda activate station_act
python --version
python -c 'import importlib.metadata as m, torch, pyarrow, datasets; print("LeRobot",m.version("lerobot"),"torch",torch.__version__,"CUDA",torch.version.cuda,"GPU",torch.cuda.is_available())'
command -v lerobot-train
nvidia-smi
```

检查数据集、两路图像、六维动作和所选 GPU 空闲后，参照[服务器适配指南](../首次Act训练文本情况.txt/SO101_数据集判定与ACT训练服务器适配指南.md)与[完整手册](../SO101采集-回放-打包-训练-本地推理全流程.md)做小步数冒烟。文档中的历史路径和状态以现场为准。

## 3. Jetson：离线检查与边缘推理

- **系统与硬件**：NVIDIA Jetson、匹配该设备的 JetPack/L4T、系统 NVIDIA 驱动/CUDA；从臂、两路相机、权限及校准仅在实际设备连接和受监督运行前配置。Git、Bash、Python、V4L2 和串口工具用于代码与设备检查。
- **Python 组件**：LeRobot（原部署环境记录为 0.6.1）、Feetech/pyserial、PyTorch、NumPy、Pillow、PyArrow、datasets、OpenCV；离线 `export` 读 Parquet 和图片，`infer` 还需 ACT 模型、PyTorch、LeRobot 及完整 checkpoint 的处理器。GPU 构建必须与 JetPack、Python 和硬件架构匹配，不能直接把 x86 或笔记本 CPU 环境搬过来。
- **原 Jetson 环境（实验性历史记录）**：`so101-act-gpu` 使用 `so101-gpu-python` 专用启动器和隔离兼容库；普通 `python` 不等价。启动器及兼容库**不包含在本仓库**，且并非适用于其他 Jetson 的通用安装方案。`so101-act` 是另一套 CPU 排错环境。不要替换已有系统 CUDA、视觉项目依赖或全局库路径；若换机，先按实际 JetPack 和 NVIDIA 兼容组件单独建设环境并重新验证。

在已配置原环境的 Jetson 上检查（环境名以实际为准）：

```bash
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate so101-act-gpu
command -v so101-gpu-python
so101-gpu-python -c 'import importlib.metadata as m, torch, numpy, pyarrow; print("LeRobot",m.version("lerobot"),"torch",torch.__version__,"CUDA",torch.version.cuda,"GPU",torch.cuda.is_available())'
```

随后使用[离线检查示例](../阶段指南/03-推理.md#无硬件离线检查示例)验证真实观测与完整 checkpoint。单次模型加载通过不证明实时性、动作安全或抓取成功；现场机械臂动作须先完成故障排除、设备核对及受监督确认。

## 不要混淆

三端的环境可以独立安装，版本不必相同；真实数据、模型及标定需另外迁移并核对。笔记本采集数据的状态/动作语义、六个关节顺序和两路图像必须与训练及推理匹配。服务器旧 Lumos 双臂 14 维脚本和模型不适用于 SO-101 单臂。历史状态记录不等于当前实时验收。

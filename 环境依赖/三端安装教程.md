# SO-101 三端依赖安装教程（新手版）

按实际设备选择对应章节：**采集笔记本 → 训练服务器 → Jetson**。每个代码块都在指定设备的终端执行，一行结束后等待完成再执行下一行。`$HOME` 表示当前用户的主目录；尖括号中的内容是示例，必须替换。安装需要网络、磁盘空间；`sudo` 会要求输入当前设备的系统密码，输入时屏幕不显示字符。不要把密码或 Token 发到聊天或写进文件。

本教程以 Ubuntu/Linux 为例，未在全新三台机器完整复现。遇到包版本、驱动或设备差异时按报错处理；已有可用环境优先复用，不要重复创建同名环境或覆盖他人环境。Git 仓库目前为私有；先按[首页](../README.md)配置有权限的 GitHub 认证并克隆到三台设备。**代码仓库不包含数据、checkpoint、机器标定和现有环境。**

## 零、公共准备：安装 Miniforge（每台缺少 conda 的机器各做一次）

如果 `conda --version` 已有输出，跳过本节，直接使用已有 conda。否则打开 [Miniforge 官方安装说明](https://github.com/conda-forge/miniforge#install)，下载与 `uname -m` 对应的 Linux 安装器、核对发布页校验值并按页面安装；安装目录选择当前用户目录，**不要覆盖已有 Miniconda/Miniforge**。例如先在终端下载并进入交互安装：

```bash
curl -fL -o "$HOME/Miniforge3.sh" "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"
bash "$HOME/Miniforge3.sh"
```

安装器会询问路径；下面假设你选择 `~/miniforge3`。后面每次打开终端先执行：

```bash
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda --version
```

如果安装在 `~/miniconda3`，把上述路径换成 `"$HOME/miniconda3/etc/profile.d/conda.sh"`。如果没有 `sudo` 权限，联系设备管理员安装系统包；服务器如已有工具可跳过系统包安装。

## 一、采集笔记本：从空环境安装到菜单

**适用：Ubuntu 图形桌面、x86_64 笔记本，主从臂及两路相机连接同一台机器。** 这个示例创建新的 `so101-collect` 环境，不修改原有 `~/so101-lab`。本项目录制适配器固定 LeRobot 0.6.1 及下述源码提交；不要用最新 main 替代。

### 1. 安装系统工具

```bash
sudo apt update
sudo apt install -y git git-lfs curl ffmpeg v4l-utils util-linux gnome-terminal build-essential cmake pkg-config
```

`v4l2-ctl` 来自 v4l-utils，`script` 来自 util-linux；菜单录制选项需要图形桌面与 gnome-terminal。检查权限，缺少时把当前用户加入设备组并**注销后重新登录**：

```bash
id -nG
sudo usermod -aG dialout,video "$USER"
```

具体设备读写仍以实际节点权限为准。新登录后重新打开终端。

### 2. 建立环境并安装固定版本

先执行公共准备中的 `source .../conda.sh`。若 `conda env list` 已有 `so101-collect`，先检查是否是自己的环境；不要盲目重建。

```bash
conda create -n so101-collect python=3.12 pip -y
conda activate so101-collect
mkdir -p "$HOME/so101-lab/src"
git clone https://github.com/huggingface/lerobot.git "$HOME/so101-lab/src/lerobot-v0.6.1"
cd "$HOME/so101-lab/src/lerobot-v0.6.1"
git checkout 7e241bd630a3719a56157a497ce5d08f244784f1
python -m pip install --upgrade pip
python -m pip install -e '.[core_scripts,feetech]'
```

若源代码目录已存在，停止克隆并先用 `git -C "$HOME/so101-lab/src/lerobot-v0.6.1" status` 和 `git ... rev-parse HEAD` 核对；有本地修改时勿切换或覆盖。`core_scripts` 安装录制所需数据、硬件和可视化依赖，`feetech` 安装电机支持；具体解析出的 PyTorch 版本可能随包源变化。[项目采集机快照](采集笔记本-pip-freeze-20261113.txt)供排查对照，不是跨平台一键锁文件。新机器的完整安装及真实录制尚未验收。

### 3. 验证、配置和启动菜单

```bash
python -m pip check
python -c 'import importlib.metadata as m, cv2, pyarrow, datasets; print("LeRobot",m.version("lerobot"),"OpenCV",cv2.__version__)'
command -v lerobot-record lerobot-find-port lerobot-find-cameras v4l2-ctl gnome-terminal script
cd "$HOME/so101-collection-training-edge-deployment"
if [ ! -e scripts/lerobot/fms688.env ]; then
  cp scripts/lerobot/fms688.env.example scripts/lerobot/fms688.env
fi
nano scripts/lerobot/fms688.env
bash scripts/lerobot/interactive_collection.sh
```

在 `nano` 填本机数据根目录、两臂串口、两路相机及任务信息；`Ctrl+O`、回车保存，`Ctrl+X` 退出。已有配置不会被上面命令覆盖。菜单选 1 预检；预检会打开相机，请先避免其他应用占用。以后每次新开终端先 `source .../conda.sh`、`conda activate so101-collect`，再进入仓库启动菜单。该方式无需原机专用的 `activate-lerobot.sh`。

现场关节故障须先解决；真实跟随、校准和录制需要现场安全确认。详见[采集指南](../阶段指南/01-采集.md)。

## 二、训练服务器：已有环境或新建隔离环境

训练服务器使用 NVIDIA GPU。先执行 `nvidia-smi`：如果找不到命令或 GPU/驱动不可用，联系管理员处理；不要自行替换共享驱动。先确认服务器上 `conda env list`、GPU、磁盘空间和他人任务；新环境及输出放自己账号下。

### 路线 A：本项目原服务器，复用老师已有环境

```bash
source /home/server/miniconda3/etc/profile.d/conda.sh
conda activate station_act
python -c 'import importlib.metadata as m, torch; print("LeRobot",m.version("lerobot"),"Torch",torch.__version__,"GPU",torch.cuda.is_available())'
command -v lerobot-train
```

该路径和 `station_act` 是原服务器的示例，其他服务器请换成真实位置。这里**不对共享环境安装或升级任何包**。原服务器还曾使用 `/mnt/soarm101_dorm/scripts/so101_codec_python.sh` 处理 torchcodec 的进程库路径问题，它不是本仓库的一键安装器。按[服务器适配指南](../首次Act训练文本情况.txt/SO101_数据集判定与ACT训练服务器适配指南.md)和[完整手册](../SO101采集-回放-打包-训练-本地推理全流程.md)读回数据并做 ACT 冒烟。

### 路线 B：新服务器，在自己账号新建 ACT 环境

先执行公共准备中的 conda 激活。下面示例**只安装在新环境**，固定服务器材料所记的 LeRobot 0.6.2 源码提交；GPU wheel 应与实际驱动兼容。示例的 CUDA 12.8 wheel 索引并非适合所有 GPU/驱动，安装前在 [PyTorch 官方选择器](https://docs.pytorch.org/get-started/locally/)确认适合的命令和索引。环境已存在时请改名，不要覆盖。

```bash
conda create -n so101-train python=3.12 pip -y
conda activate so101-train
python -m pip install --upgrade pip
# 以下 CUDA 12.8 示例仅在官方选择器确认适配当前驱动后执行
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
mkdir -p "$HOME/so101-train-src"
git clone https://github.com/huggingface/lerobot.git "$HOME/so101-train-src/lerobot"
cd "$HOME/so101-train-src/lerobot"
git checkout 3f2c29ef7e44b1ddccbcda3b6a63939e53639e9e
python -m pip install -e '.[training]' 
python -m pip check
python -c 'import importlib.metadata as m, torch, pyarrow, datasets; print("LeRobot",m.version("lerobot"),"Torch",torch.__version__,"GPU",torch.cuda.is_available())'
command -v lerobot-train
```

安装前如果 `~/so101-train-src/lerobot` 已存在，请先检查，不要覆盖。该固定源码的 `pyproject.toml` 标识为 0.6.2；不能假设 PyPI 一定提供同版。上面安装是**新服务器方案，尚未在目标服务器端到端验证**；包解析可能改变 PyTorch 版本，所以务必重新检查 `torch.cuda.is_available()` 和 `nvidia-smi`。先传完整任务/版本的数据包、校验解包、读回双相机与六维动作，才执行小步数 ACT 训练；多 GPU、SmolVLA 和 VQ-BeT 的额外依赖不在本教程的验收范围。若 torchcodec 或 CUDA 加载报错，保留错误并在独立环境处理，不要修改共享环境。

## 三、Jetson：为边缘推理安装

### 1. 先确认设备和 JetPack

在 Jetson 终端运行：

```bash
uname -m
cat /etc/nv_tegra_release
cat /etc/os-release
```

一般应是 `aarch64`；JetPack/L4T、Python、GPU wheel 必须匹配。不同版本不能通用同一个 PyTorch wheel；参考 [NVIDIA Jetson PyTorch 安装教程](https://docs.nvidia.com/deeplearning/frameworks/install-pytorch-jetson-platform/index.html)和[兼容矩阵](https://docs.nvidia.com/deeplearning/frameworks/install-pytorch-jetson-platform-release-notes/pytorch-jetson-rel.html)。不要重装系统 CUDA，也不要动现有摄像头网页的环境。

### 2. 新建 CPU 排错环境（不驱动机械臂）

此路径有原项目的历史安装记录；换机未端到端验证。先使用公共准备激活 conda。确认没有同名环境后执行：

```bash
conda create -n so101-act-cpu -c conda-forge python=3.12 pip -y
conda activate so101-act-cpu
python -m pip install --upgrade pip
python -m pip install --index-url https://download.pytorch.org/whl/cpu 'torch==2.7.1' 'torchvision==0.22.1'
python -m pip install 'lerobot[feetech]==0.6.1' 'torch==2.7.1+cpu' 'torchvision==0.22.1'
python -m pip install 'datasets>=4.8,<5' 'pandas>=2,<3' 'pyarrow>=21,<30' 'av>=15,<16' 'jsonlines>=4,<5'
python -m pip check
python -c 'import torch; from lerobot.policies.act.modeling_act import ACTPolicy; import scservo_sdk; print("Torch",torch.__version__,"CUDA",torch.cuda.is_available(),"ACT/Feetech OK")'
```

这用于无硬件 CPU 检查，不代表速度满足实机控制。若 wheel 不支持该 JetPack/Python，停止并按官方兼容信息选方案，不要强行降级系统库。

### 3. GPU 环境：原 Jetson 与新 Jetson 分开

**本项目原 Jetson 已有 `so101-act-gpu`**，可先按[三端依赖检查](三端运行依赖.md)激活并检查 `so101-gpu-python`。该启动器、私有兼容库与关闭 cuDNN 的处理是原设备的实验实现，**不在仓库中**；仅复制 Python 包或运行 `pip install` 无法重建。历史过程见[完整手册第 9 节](../SO101采集-回放-打包-训练-本地推理全流程.md)，不要把其中的特定轮子或系统库兼容步骤直接用到不同 Jetson。

**新 Jetson**：先依据上述 NVIDIA 兼容矩阵选择对应 JetPack、Python 和 GPU wheel，按 NVIDIA 官方安装指南在独立环境安装 PyTorch，再检查 GPU 矩阵运算。随后需要匹配的 torchvision 和 LeRobot 依赖；安装时检查解析器不会替换刚选好的 Jetson PyTorch。此项目**尚没有经过新机验证的 GPU 一键安装方案**；选不到兼容 wheel、遇到版本冲突或缺少原启动器时先停在离线 CPU 路线并保留报错，不能宣称 GPU 部署已完成。

CPU 环境激活后，在仓库目录按[离线检查示例](../阶段指南/03-推理.md#无硬件离线检查示例)用 `python ... infer --device cpu` 运行真实观测；确认模型和相机输入的兼容性。GPU 环境只在确认安装完成后再进行相同离线检查。真实机械臂执行前需单独核对串口、校准、摄像头与现场停止方式。

## 常见问题

- `conda: command not found`：本终端没有 `source` 正确的 conda.sh；确认实际安装路径。
- `lerobot-record: command not found`：确认激活采集环境，重新执行采集端的 `.[core_scripts,feetech]` 安装和 `pip check`。
- `Permission denied`：核对当前 `id -nG` 和实际设备节点权限；加组后注销重登，再检查连接。
- `CUDA ... False`：检查当前环境 Python、驱动与 GPU wheel 匹配；CPU 环境显示 False 是预期，不要用它判断 GPU 环境。
- 下载失败或找不到包：检查网络、Python 版本与包源；不要把密钥写入命令行历史或仓库。
